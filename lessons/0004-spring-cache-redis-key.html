Spring Cache Redis Key 生成机制

理解 @Cacheable 的 value、key、cacheNames 以及 RedisCacheConfiguration 中的 computePrefixWith 如何协同工作

一、核心公式（记住这个就够了）

最终 Redis Key = prefix + key

其中：

1prefix（前缀） = computePrefixWith 函数的返回值，默认是 cacheName + ":"
2key（具体键） = @Cacheable 的 key 属性，由 SpEL 表达式或 KeyGenerator 生成

二、@Cacheable 注解的各个属性

属性作用是否必须示例
value缓存名称（namespace），用于分组必须"shopStatus"
cacheNames和 value 完全一样，是别名二选一{"dish", "setmeal"}
key缓存的具体键，SpEL 表达式可选"#id"、"'STATIC_KEY'"
keyGenerator自定义 Key 生成器 Bean可选"myKeyGenerator"
condition方法执行前判断是否缓存可选"#id > 0"
unless方法执行后判断是否不缓存可选"#result == null"
关键区分：value（或 cacheNames）决定的是缓存分组/命名空间，不是 Redis 里的完整 key。key 才是 Redis key 的后半部分。

三、RedisCacheConfiguration 中的 computePrefixWith

这是你项目里 RedisConfiguration.java:56 的配置：

.computePrefixWith(cacheName -> !cacheName.isEmpty() ? cacheName + ":" : "AAA")

这个函数的作用：

  • 接收 cacheName（即 @Cacheable 的 value）
  • 返回一个前缀字符串
  • 你的配置：如果 cacheName 不为空，前缀就是 cacheName + ":"；否则是 "AAA"

四、完整流程：从注解到 Redis Key

场景 A：你当前的代码（key = "''"）

@Cacheable(value = "shopStatus", key = "''", unless = "#result == null")
public Integer getStatus() { ... }
1value = "shopStatus" → cacheName = "shopStatus"
2computePrefixWith("shopStatus") → 返回 "shopStatus:"
3key = "''" → SpEL 解析为空字符串 ""
4最终 Redis Key = "shopStatus:" + "" = "shopStatus:"
问题：key = "''" 生成的是空字符串 key，Redis 里会显示为 shopStatus::（双冒号），这不是你想要的。

场景 B：不指定 key（默认行为）

@Cacheable(value = "shopStatus", unless = "#result == null")
public Integer getStatus() { ... }  // 无参数
1没有指定 key，Spring 使用默认的 SimpleKeyGenerator
2方法没有参数 → 生成 SimpleKey []
3最终 Redis Key = "shopStatus:" + "SimpleKey []" = "shopStatus::SimpleKey []"

场景 C：指定固定字符串 key（推荐）

@Cacheable(value = "shopStatus", key = "'SHOP_STATUS'", unless = "#result == null")
public Integer getStatus() { ... }
1key = "'SHOP_STATUS'" → SpEL 中单引号包裹的是字符串字面量
2解析结果为 "SHOP_STATUS"
3最终 Redis Key = "shopStatus:" + "SHOP_STATUS" = "shopStatus:SHOP_STATUS"
这就是你想要的效果！Redis 里显示为 shopStatus:SHOP_STATUS，清晰明了。

五、SpEL 表达式中 key 的写法规则

写法含义结果示例
key = "#id"取方法参数 id 的值方法传 42 → key = "42"
key = "#user.id"取方法参数 user 对象的 id 属性user.id = 100 → key = "100"
key = "'STATIC'"字符串字面量（注意外层双引号 + 内层单引号）key = "STATIC"
key = "''"空字符串字面量key = ""
key = "#root.methodName"取方法名方法名 getStatus → key = "getStatus"
最容易混淆的点：
Java 注解中 key = "'SHOP_STATUS'" 看起来有三层引号，其实是两层：
- 外层 "..." 是 Java 字符串的引号
- 内层 '...' 是 SpEL 表达式的字符串字面量标记
所以实际传给 SpEL 解析器的是 'SHOP_STATUS'，它解析为字符串 SHOP_STATUS。

六、你的项目中各层配置的关系

┌─────────────────────────────────────────────────────────┐
│  @Cacheable(value = "shopStatus", key = "'SHOP_STATUS'") │  ← Service 层：指定 cacheName 和具体 key
│                         ↓                                │
│  computePrefixWith(cacheName → cacheName + ":")          │  ← 配置层：指定前缀规则
│                         ↓                                │
│  Redis Key = "shopStatus:" + "SHOP_STATUS"               │  ← 最终结果
│                  = "shopStatus:SHOP_STATUS"              │
─────────────────────────────────────────────────────────┘

七、小测验

测验 1

以下代码的 Redis Key 是什么？

@Cacheable(value = "dish", key = "#categoryId")
public List<Dish> list(Integer categoryId) { ... }

// 调用：list(5)
A. dish:5 B. dish::5 C. dish:categoryId D. dish:#categoryId
答案：B — prefix = "dish:"，key = "5"（categoryId 的值），中间有 computePrefixWith 加的冒号，所以是 dish::5（注意双冒号：前缀自带一个，key 前面 Spring 还会加一个分隔符 ::）。

测验 2

以下代码的 Redis Key 是什么？

@Cacheable(value = "config", key = "'APP_NAME'")
public String getAppName() { ... }
A. config:APP_NAME B. config::APP_NAME C. config:'APP_NAME' D. APP_NAME
答案：B — prefix = "config:"，key = "APP_NAME"（SpEL 字符串字面量），Spring Cache 默认用 :: 连接 prefix 和 key，所以是 config::APP_NAME。

测验 3

value 和 cacheNames 的关系是？

A. value 是 Redis key，cacheNames 是分组名 B. value 是前缀，cacheNames 是后缀 C. 完全等价，只是别名关系 D. value 用于读缓存，cacheNames 用于写缓存
答案：C — value 和 cacheNames 完全等价，cacheNames 是 value 的别名（Spring 4.2+ 引入，支持数组形式指定多个缓存名称）。
